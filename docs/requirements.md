# OneNote Ferry 需求文档

版本：草案 0.2（2026-11-24）

## 1. 背景

很多人多年来用 OneNote 记笔记，现在想搬到 Obsidian：Markdown 文件属于自己，能长期保存，也能交给 AI 工具阅读。但对 Mac 用户来说，现有的迁移路线都有明显的缺口：

1. Mac 版 OneNote 只能导出 PDF。
2. 大多数高还原度的转换工具依赖 Windows 版 OneNote（往往还需要 Word）。
3. Obsidian 官方导入插件读取 OneNote 账号时依赖微软接口，速度受限，格式丢失较多；它的文件导入只支持 Windows 版导出的文件。
4. 在 OneDrive 网页上把存放笔记本的文件夹下载下来，可以拿到全部原始笔记文件，但这种文件是 OneDrive 自己的打包格式，能读它的工具很少，现有的几个要么只能导进别的软件，要么转换时会丢掉整个分区或全部高亮。

## 2. 用户痛点

1. 用 Mac，没有 Windows 电脑，或者 Windows 导出太慢。
2. 笔记量大（几十个笔记本、上千页），截图、扫描件、PDF 附件很多。
3. 依赖高亮颜色、自由文本框、笔记间链接来组织思路，迁移后这些东西一丢，笔记就失去了一半的价值。
4. 迁移后很难发现丢了什么，没法放心删掉 OneNote。
5. OneNote 还要再用一段时间，迁移不是一次性的，希望以后能把新增和修改的内容同步过去。

## 3. 项目目标

1. 在 Obsidian 里（Mac、Windows、Linux 桌面版）直接读取从 OneDrive 下载的 OneNote 笔记，转成整理好的 Markdown 文件夹。
2. 还原度：文字与格式、高亮颜色、链接、原始图片与附件、页面层级、文本框阅读顺序都保留；做不到的地方在原位说明，不悄悄丢弃。
3. 对账：每次转换生成报告，说明转了多少、哪些失败、哪些附件缺失。
4. 增量同步：以后重新下载笔记，只更新变化的分区，旧版本留存可回退。
5. 安全：只读源文件，只写用户指定的文件夹。

## 4. 非目标

1. 不还原 OneNote 的自由画布版面（字号、字体、精确位置）。输出坚持纯 Markdown，位置信息以注释形式记录。
2. 不做双向同步，不把 Obsidian 的修改写回 OneNote。
3. 不通过 OneNote 内容接口读取笔记（限流严重，格式损失大）。如果加入插件内直接下载，也只读取原始笔记文件，数据从微软直接到用户电脑。
4. 不迁移 OneNote 以外的笔记软件。
5. 不在服务器上处理任何用户数据，全部在本机完成。

## 5. MVP 功能范围

### 5.1 必须有（第一个公开版本）

1. 导入向导：选择 OneDrive 下载的 zip（无须解压，可一次选多个）或解压后的文件夹，列出笔记本和分区，可部分选择。附简短的下载引导（大笔记本建议一本一本下载）。
   1. 下载包不完整时，能读的分区照样列出和导入，读不全的分区标明原因，并说明需要重新下载哪几本笔记本。
   2. 有密码的分区给出明确提示（请在 OneNote 里取消密码后重新下载）。
2. 转换前预览：目标文件夹（默认 `OneNote`，可改）、页面与附件数量、所需空间。目标文件夹里已有同名笔记本时不覆盖，可以换个名字导入。
3. 转换：
   1. 文字格式：粗体、斜体、下划线、删除线、上下标。
   2. 高亮：保留，并用彩色圆点标出颜色。
   3. 链接：网页链接完整可点；笔记间链接改写为库内相对链接。
   4. 图片与附件：原始文件，同一分区内去重，按页面标题命名。
   5. 页面层级与目录：每个笔记本、分区有目录文件，子页面层级保留。
   6. 文本框：按版面分栏排出阅读顺序，并用注释记录每块的位置。
   7. 手写：笔迹按它在页面上的位置放回正文，画成 SVG 图片，深色主题下黑色笔迹自动变白；画在图片或打印页上的笔迹（含荧光笔）和那张图合成一张；其他地方的荧光笔笔迹不导出。
   8. 打印页：有原 PDF 时显示 PDF 的对应页；页面上有批注时逐页显示，批注画在对应页上。
   9. 数学公式：转成 LaTeX。
   10. 页面属性：标题、所属分区、顺序、层级、创建与修改时间、页面 ID。
   11. 做不到的地方在原位留提示（附件或图片在下载包里没有数据、分区读不出）。
4. 进度显示、可取消；取消时写完正在转换的分区再停，已写内容完整。
5. 转换报告：一页可读的笔记，加一份供以后同步使用的数据文件，文字跟随 Obsidian 的界面语言。
6. 多语言：
   1. 界面四语：English、中文、日本語、한국어。
   2. 转换时插入文档的文字（文本框位置注释、附件缺失提示、目录说明、附件文件名与文件夹名）跟随笔记的语言：English、简体中文、繁體中文、日本語、한국어。以笔记本为单位自动识别，导入前可以修改；页面属性名保持英文，方便查询。
7. 命令行版本：与插件共用同一套核心，供批量处理与自动化。

### 5.2 紧随其后

1. 插件内直接下载：登录微软账号，按分区直接下载原始笔记文件（可断点续传），同步时只下载变了的分区。
2. 增量同步：「检查 OneNote 更新」，预览变化后确认执行；旧版移入 `_旧版本/`；修复链接；生成更新记录。
3. 支持 Windows 版 OneNote 导出的 .one 与 .onepkg 文件。

## 6. 成功标准

1. 在维护者自己的大型笔记库（200 多个分区、1,700 页、一万多个附件）上，所有分区转换成功，附件引用零缺失，本地链接零断链。
2. 已知的每种情形（各种格式、高亮、链接、文本框、附件、手写、语言）都有自动化测试覆盖。
3. 最大的单个分区（约 1.7 GB）可以在插件内完成转换，或给出明确的替代方案。
4. 一个没有用过的人，按照 README 能在 15 分钟内完成第一次导入。
5. 通过 Obsidian 社区插件审核。

## 7. 风险与约束

1. **插件内存**：解析器以 WebAssembly 运行时，内存上限可能不足以处理超大分区。需要尽早压测，必要时分批或提供命令行替代。
2. **文件格式变化**：OneDrive 下载格式没有公开规范，微软改动可能导致解析失败。依赖上游解析器的维护，并定期重新下载笔记验证。
3. **许可**：解析器来自 Joplin（MPL-2.0），Markdown 写出部分来自 Obsidian Importer（MIT）。插件以 MIT 发布，MPL 文件保持原许可并公开源码。
4. **工作或学校账号**：目前只在个人账号的下载包上验证过；微软说明这类账号在网页上不能下载笔记本，可能需要在插件内直接下载。
5. **网页下载中断**：大文件夹的网页下载可能中途失败且不能续传，需要引导用户按笔记本逐个下载，并做好残缺下载包的兜底。
6. **分区顺序**：下载包里没有分区顺序信息，目前按名称排序。

## 8. 后续增强

1. 分区手动排序，或读取用户提供的顺序。
2. 可选导出图片以外的荧光笔笔迹。
3. 转换报告的可视化。
4. 与官方导入插件合作，把读取 OneDrive 下载文件的能力贡献上游。
