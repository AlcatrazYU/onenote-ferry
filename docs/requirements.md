# OneNote Ferry 需求文档

版本：草案 0.9（2026-11-28）

## 1. 背景

很多人多年来用 OneNote 记笔记，现在想搬到 Obsidian：Markdown 文件属于自己，能长期保存，也能交给 AI 工具阅读。但对 Mac 用户来说，现有的迁移路线都有明显的缺口：

1. Mac 版 OneNote 只能导出 PDF。
2. 大多数高还原度的转换工具依赖 Windows 版 OneNote（往往还需要 Word）。
3. Obsidian 官方导入插件读取 OneNote 账号时依赖微软接口，速度受限，格式丢失较多；它的文件导入只支持 Windows 版导出的文件。
4. 在 OneDrive 网页上把存放笔记本的文件夹下载下来，可以拿到全部原始笔记文件，但这种文件是 OneDrive 自己的打包格式，能读它的工具很少，现有的几个要么只能导进别的软件，要么转换时会丢掉整个分区或全部高亮。

## 2. 用户痛点

1. 用 Mac，没有 Windows 电脑，或者 Windows 导出太慢。
2. 笔记量大（几十个笔记本、上千页），截图、扫描件、PDF 附件很多。
3. 依赖高亮颜色、自由文本框、笔记间链接来组织思路，迁移后这些东西一丢，笔记就失去了一半的价值。
4. 迁移后很难发现丢了什么，没法放心删掉 OneNote。
5. OneNote 还要再用一段时间，迁移不是一次性的，希望以后能把新增和修改的内容同步过去。

## 3. 项目目标

1. 在 Obsidian 里（Mac、Windows、Linux 桌面版）读取 OneNote 笔记（登录微软账号后在插件里从 OneDrive 直接下载，或用 OneDrive 网页上下载的文件夹，或用 Windows 版 OneNote 导出的文件），转成整理好的 Markdown 文件夹。
2. 还原度：文字与格式、高亮颜色、链接、原始图片与附件、页面层级、文本框阅读顺序都保留；做不到的地方在原位说明，不悄悄丢弃。
3. 对账：每次转换生成报告，说明转了多少、哪些失败、哪些附件缺失。
4. 检查更新：以后重新下载笔记，只更新变化的页面和分区，换下来的版本留存，任何东西都不删除。
5. 安全：只读源文件，只写用户指定的文件夹。

## 4. 非目标

1. 不还原 OneNote 的自由画布版面（字号、字体、精确位置）。输出坚持纯 Markdown，位置信息以注释形式记录。
2. 不做双向同步，不把 Obsidian 的修改写回 OneNote。
3. 不通过 OneNote 内容接口读取笔记（限流严重，格式损失大）。插件内直接下载也只读取原始笔记文件，只要读取权限，数据从微软直接到用户电脑。
4. 不迁移 OneNote 以外的笔记软件。
5. 不在服务器上处理任何用户数据，全部在本机完成。

## 5. MVP 功能范围

### 5.1 已经做好的

1. 导入窗口：笔记本有两种来源，“从 OneDrive 导入”（见第 9 项）和“选择文件或文件夹”（OneDrive 网页上下载的 zip 或解压后的文件夹，或 Windows 版 OneNote 导出的整本笔记本 `.onepkg`、单个分区 `.one`，可一次选多个；Windows 和 Linux 上分成“选择文件”和“选择文件夹”两个按钮），两行的说明在鼠标悬停时显示。单个 `.one` 算作只有这个分区的笔记本，名字取文件名；几个分区想放进一本，就把它们放进一个文件夹再选文件夹。以树的形式列出笔记本、分区组和分区，按笔记本或分区勾选；没选的分区在笔记本目录页里标“未导入”；只导入了一部分的笔记本在树里标“部分导入”。不支持按页面选择。
   1. 下载包不完整时，能读的分区照样列出和导入，读不全的分区标明原因，并提示重新下载。
   2. 有密码的分区给出明确提示（请在 OneNote 里取消密码后重新下载）。
   3. 开始之前关掉导入窗口，只是把它藏起来：选好的来源、勾选和设置都留着，到退出 Obsidian 为止；还没读完或没检查完的在后台继续，状态栏显示进度，点它打开窗口。左侧图标、两个命令和设置页打开的都是这个窗口。再次打开时先核对：磁盘上改过的下载重新读取（勾选保留，没变的分区不重读），找不到的标明，移除之前不能开始；OneDrive 重新读取清单，已导入的笔记本在副本里补上改过的文件、只重读改过的分区；目标文件夹也重新看一遍。点开始时再核对一次：下载改过就重新读取、不开始；勾选的 OneDrive 笔记本按 OneDrive 当时的样子下载。窗口里没有来源时关掉，下次就是新的窗口。
   4. 同时选了几个来源时，树按来源分组，每个来源名字前有一个勾，可以一次勾选或取消这个来源的全部笔记本（规则和“全选”一样）。还没导入过的同名笔记本在几个来源里都勾上，会各导入一份（第二份叫“名字 (2)”）；只按名字判断，导入前分不出是不是同一本，所以窗口底部用一行字说明会分别导入并加“(2)”，如为同一本请只勾选一处。已导入过的笔记本出现在几个来源里，只用较新的一份更新。
2. 导入前显示目标文件夹（默认 `OneNote`，可改；开始导入或更新时记下这次用的文件夹，下次打开窗口就从它开始）和将导入的笔记本、分区数量与大小。目标文件夹里已有以前导入的这本笔记本时，这本走“检查更新”（第 8 项）：新分区补进原来的文件夹，已导入的分区只在 OneNote 里有变化时才更新。从 OneDrive 来的笔记本按 OneDrive 的编号认（第 9 项第 9 条）；下载的文件夹和 Windows 导出的文件没有编号，按名字认：两本不同的同名笔记本（例如两个 OneDrive 账号里各一本），请导入到不同的目标文件夹。同名文件夹或分区文件夹不是导入时建的（没有带导入状态的目录页）时，一个文件都不写进去。页面写法的三项设置按分区记：第一次写入的分区（新导入的、补进来的、上次没写完的）和重新转换的分区（第 8 项第 11 条）用窗口里当时的设置，因 OneNote 有更新而更新的分区沿用自己原来的；目录和提示的语言按笔记本记。勾了有更新的分区时，窗口底部写明“有更新的分区沿用原来的设置”；什么都没勾时，三项设置可以先改。导入中途停止、关掉插件或退出 Obsidian 后，再导入一次就能补齐没写完的分区；同一本笔记本里页面之间的链接边导入边改写，退出 Obsidian 时只有跨笔记本的链接要等以后更新时再改写。
3. 转换：
   1. 文字格式：粗体、斜体、下划线、删除线、上下标；彩色文字保留原来的颜色（黑色、灰色当作默认颜色）。这是 OneNote 里原有的信息，一律保留，不设开关。能用 Markdown 写的都用 Markdown（`**`、`*`、`~~`、`==`），方便以后接着编辑；只有 Markdown 写不了的（颜色、下划线、上下标）用 HTML，这些字的粗体、斜体、删除线写在它自己的 HTML 里。写法让 Obsidian 的编辑视图也认得（例外见第 9 节）：粗体两端紧挨标点、外面又是文字时，那个标点不加粗（否则编辑视图不认 `**`）；有粗体的段落里，原文自己的星号写成 `\*`。颜色、下划线、上下标的 HTML 里，只给阅读视图会当成 Markdown 的符号加反斜杠（编辑视图会把反斜杠原样显示）。
   2. 高亮：保留，并用彩色圆点标出颜色。
   3. 链接：网页链接完整可点；笔记间链接改写为仓库内的相对链接。
   4. 图片与附件：原始文件，同一分区内去重，按页面标题命名。TIF 图片转成像素完全相同的 PNG（转不了的，如带旋转标记的，给链接加说明）；Obsidian 显示不了的格式（EMF 等）给链接加说明。Windows 导出的图片没有扩展名时按文件内容认类型。
   5. 页面层级与目录：每个笔记本、分区有目录文件，子页面层级保留。分区按 OneNote 里的顺序排（读笔记本的目录文件 `.onetoc2`；目录里没列的排在后面，按名称），每一层分区在前、分区组在后。
   6. 文本框：按版面分栏排出阅读顺序，并用注释记录每块的位置（只在多栏的页面上，只写在有内容的块前面）。
   7. 手写：笔迹按它在页面上的位置放回正文，画成 SVG 图片，深色主题下黑色笔迹自动变白；压在手写上的荧光笔画进同一张手写图（正片叠底）。图片上的笔迹（手写和荧光笔合在一起，白色底，颜色不变）：直接放在页面上的图片和 Mac 版打印页，位置文件里有，照实画进图里；文本框里的图片，文件里不记它的位置，按排版估算，再读图片像素（PNG 和 JPEG）对齐到文字行，有把握的画进图里，没把握的图片保持原样，下面跟一个折叠框（标题“笔迹（位置为估算）”），里面是按估算位置画上全部笔迹的副本，不加开关。表格格子里的图片同样按估算放：列宽取文件里的，行高取这一行最高的格子，加上 OneNote 画表格时的边距（在测试页上量出），比格子宽的图按 OneNote 的做法缩到格子宽；有把握的画进格子里的图，没把握的折叠框放不进表格，放在表格下面，每张前面写明“第几行第几列”。打字文字上和空白处的荧光笔不导出（要强调的打字文字通常直接用文字高亮）。
   8. 打印页：有原 PDF 时（同一页里或同一分区里）显示 PDF 的对应页；没有原 PDF 的 Windows 版打印页（Word 打印的、原件不在笔记本里的）从 XPS 画成 SVG，每页一张，下面留原文件的链接。XPS 里的文字按文件写明的字形编号，从文件自带的字体里取字形画出，并用字体的字符表和替换表核对，一页里有一处对不上就不画这一页，只给链接，报告里写明（宁可不显示，也不显示错的）。Mac 版打印页（每页一张图）上有批注时，这份文件逐页显示，批注画在对应页上。Windows 版打印页（整份文档存成一个 XPS）上有批注时，从 XPS 里取出这一页的图片和图形画成 SVG，批注画在上面，放在 PDF 那一页后面；文本框里的打印页按第 7 条，位置没把握时折叠。这一页画不出来（比如里面是矢量文字）时，批注画在 PDF 那一页后面一张同样大小的空白纸上。同一份 PDF 连着的几页只放一个预览（Obsidian 的 PDF 预览能翻看整份文档），这几页上的批注统一放在预览后面；位置没把握的放进一个折叠框，每张前面写明是第几页。
   9. 图片里的文字：
      1. 打印页的文字总是写，放在每页下面一个默认收起的提示框里。Windows 版打印页写打印件里写明的文字，标题“打印页上的文字”；OneNote 存的识别文字和它不同时（扫描件）再写一个“OneNote 识别的文字（可能有错）”。Mac 版打印页只有识别文字。
      2. 普通图片的替换文字和 OneNote 识别的文字由“图片里的文字”开关控制，默认关闭（命令行 `--image-text`）。表格单元格里的图片不写提示框。
      3. 识别文字的整理：连续三行以上、每行只有一两个字的连成一行；汉字、假名之间 OneNote 加的空格去掉。打印件自己写的文字和替换文字不改。
   10. 数学公式：转成 LaTeX。
   11. 页面属性：标题、所属分区、顺序、层级、创建与修改时间、页面 ID。
   12. 做不到的地方在原位留提示（附件或图片在下载包里没有数据、分区读不出）。
4. 进度显示、可停止；停止时写完正在转换的分区再停，已写内容完整。
5. 转换报告：一页可读的笔记，加一份供以后同步使用的数据文件，文字跟随 Obsidian 的界面语言。它是整个文件夹的总览（有哪些笔记本、哪些内容没能转换），开头写明这一点，并指向记录每次更新的“更新记录”。导入过程中每写完一个分区就更新一次，中途退出 Obsidian 时已写的内容不会从报告里丢失。
6. 多语言：
   1. 界面四语：English、中文、日本語、한국어。
   2. 转换时插入文档的文字（文本框位置注释、附件缺失提示、目录说明、附件文件名与文件夹名）有五种：English、简体中文、繁體中文、日本語、한국어。默认跟随 Obsidian 的界面语言，导入前可以修改；补进已有笔记本的分区沿用这本原来的语言；页面属性名保持英文，方便查询。
7. 命令行版本：与插件共用同一套核心，供批量处理与自动化；`sync` 命令做检查更新（默认只预览）。
8. 检查更新（增量同步）：
   1. 命令“检查 OneNote 更新”打开同一个导入窗口；在导入窗口里选进重新下载的包或重新导出的文件也一样。已导入的笔记本逐个分区读页面信息，与仓库里的比较；每个分区写明状态（无变化、有更新、新分区、上次未完成、上次未选、已不在仓库中、下载的版本较旧、下载中没有等），有更新的分区可以展开看每一页的变化。
   2. 默认勾选：有更新、新分区、上次没写完的勾上；导入时有意没选的、以前导入过现在找不到的、下载比仓库里旧的、从没导入过的笔记本不勾。
   3. 原地更新：只换 OneNote 里改过的页面，换之前把仓库里那份复制进 `_旧版本/<时间>/`；没改的页面一个字节不动，书签、白板、打开的标签页留在活页面上；用户放进分区文件夹的文件不动；OneNote 里改了名或换了分区组的分区，文件夹原地改名。
   4. OneNote 里改了、用户在 Obsidian 里也改过的页面：换成 OneNote 的新版，用户的版本另存在 `_旧版本` 里，窗口、完成页、更新记录都标出。只在 Obsidian 里改过的页面保持用户的版本。
   5. OneNote 里没有、仓库里有的一律不动：OneNote 删掉的页面留在原处（分区目录页单列），新下载里没有的分区保持原样。
   6. 用户在 Obsidian 里删掉的页面，插件从不自己补回（更新、重新转换、全选都一样）。分区展开后这一页标“Obsidian 中已删除”，鼠标停上去提示“勾选后补回”；勾上后分区显示“补回 N 页”，这一页按分区原来的设置转。点分区只管重新转换（鼠标停上去写明删掉的页不会补回），勾页只管补回。
   7. 从不删除文件；`_旧版本` 由用户确认新版无误后自己删。
   8. 每次更新写一页更新记录（`_更新记录/`），开头写明它记的是这次更新对已导入的笔记本做了什么（包括补进的分区），并链接到转换报告；正文列出变化、需要注意的地方和两个版本的链接。转换报告的“最近一次导入”链接到它；一次运行先导入新笔记本、再更新已导入的笔记本时，“最近一次导入”算整次。
   9. 中途退出 Obsidian：下次打开时自动处理完毕，每个分区要么全旧、要么全新。
   10. 同一本笔记本的新旧两份下载一起选时，只用较新的那份更新。
   11. 重新转换：“无变化”的分区默认打灰色的勾，表示已导入、无事可做；点一下变成正常的勾，标“重新转换”，再点一下恢复。笔记本或分区组下全是这种分区时，点它就整本（整组）重新转换。鼠标停在这种行上（包括勾）提示“点击后按现在的设置重新转换”；没有更新时，底部写“没有发现更新。点击分区可以按现在的设置重新转换。”。“全选”在有要更新或要导入的分区时只勾这些；一个都没有时，勾上全部“无变化”的分区，即全部重新转换。重新转换按窗口里现在的设置重写整个分区，旧版放进 `_旧版本`；在 Obsidian 里改过的页保持原样，在更新记录里列出。不加开关或新命令；命令行版暂不提供。
9. 插件内直接下载（OneDrive）：
   1. 登录：在系统浏览器里打开微软的登录页（授权码流程加 PKCE），由本机 127.0.0.1 上的一次性接收端收回结果；插件看不到密码。之后浏览器里显示的页面由插件给出，标题直接说结果（已登录、登录没有完成、这次登录已经结束），常见的失败原因（取消或没有同意、单位要求管理员批准）用一句话说明，微软的原话附在后面。只请求读取文件（`Files.Read`）、保持登录（`offline_access`）和基本登录资料（`openid`、`profile`）。刷新令牌存在 Obsidian 的密钥存储里，不写进插件的设置文件；设置页可以退出登录，并写明到哪里收回授权。
   2. 找笔记本：列出“文档”文件夹里的笔记本，并在整个 OneDrive 里按目录文件搜索其他位置的笔记本；列表里没有的，可以在“在其他文件夹里找”里打开文件夹挑选。上次的清单先显示，同时在后台向 OneDrive 核对最新的。只列用户自己 OneDrive 里的笔记本。
   3. 选择：按 OneDrive 的文件清单列出笔记本和分区，这时不下载；默认不勾（和官方导入插件一样），勾选可以随时改。点“开始导入”后只下载勾上的分区，再按下载的文件夹导入。
   4. 检查更新：已导入的笔记本先整本更新到本地副本（只下载 OneDrive 上变了的文件），再和以前一样逐个分区比较。
   5. 本地副本：放在仓库外的系统缓存文件夹里，结构和网页下载的 zip 相同；下载前检查剩余空间；设置页的“下载缓存”显示占用和位置，可以清除（先确认）。
   6. 下载：流式写盘，内存不随文件变大；断网、链接过期、服务繁忙时从已下载的位置接着下；每段回应都核对版本标记，下载途中文件在 OneDrive 上变了就从头重下，不会拼出新旧两半；可以停止。
   7. 有密码的分区下载后才能看出，照导入的规矩写进报告，算作没有转换。
   8. 只连接微软（登录、Microsoft Graph、微软的文件服务器），没有遥测；命令行版不接直接下载。
   9. 按编号认笔记本：从 OneDrive 导入或更新的笔记本，目录页的属性（`onedrive-notebook`）和转换报告里记下它在 OneDrive 上的编号（账号和笔记本）。检查更新时先找目标文件夹第一层里目录页带同一编号的文件夹，不管它叫什么（在 Obsidian 里改过名也找得到）；找不到再按名字认，认出后补记编号。编号只在同一个账号里算数，换了账号按名字认。同名文件夹带着同一账号另一本笔记本的编号时，这本是另一本（如复制出来的），导入为“名字 (2)”，以后各自更新。笔记本在 OneNote 里改了名：照常更新，目录页和报告里的名字换成新的；文件夹还是导入时的名字时跟着改名（`Vault.rename`，和分区改名一样），用户自己改过的或新名字已被占用的不改，更新记录里写明。

## 6. 成功标准

1. 在维护者自己的大型笔记库（200 多个分区、1,700 页、一万多个附件）上，所有分区转换成功，附件引用零缺失，本地链接零断链。
2. 已知的每种情形（各种格式、高亮、链接、文本框、附件、手写、语言）都有自动化测试覆盖。
3. 最大的单个分区（约 1.7 GB）可以在插件内完成转换，或给出明确的替代方案。
4. 一个没有用过的人，按照 README 能在 15 分钟内完成第一次导入。
5. 检查更新：维护者的真实笔记重新下载后，用新旧两份下载走一遍检查更新，结果与直接导入新版相同（用户自己的改动除外）。
6. 直接下载：维护者的全部笔记本直接下载后与同一天网页下载的 zip 逐字节相同；用直接下载导入的结果与命令行导入网页 zip 的结果逐文件相同。
7. 通过 Obsidian 社区插件审核。

## 7. 风险与约束

1. **插件内存**：解析器以 WebAssembly 运行时，内存上限可能不足以处理超大分区。需要尽早压测，必要时分批或提供命令行替代。
2. **文件格式变化**：OneDrive 下载格式没有公开规范，微软改动可能导致解析失败。依赖上游解析器的维护，并定期重新下载笔记验证。
3. **许可**：解析器来自 Joplin（MPL-2.0），Markdown 写出部分来自 Obsidian Importer（MIT），`.onepkg` 的解压来自 OfficeIMO（MIT，经 Obsidian Importer）。插件以 MIT 发布，MPL 文件保持原许可并公开源码。
4. **工作或学校账号**：目前只在个人账号上验证过。有的组织要管理员先批准第三方应用，插件才能登录（实测过一个学校账号，显示需要批准）；微软说明这类账号在网页上不能下载笔记本。世纪互联运营的中国版账号登录不了全球的应用，不支持。
5. **网页下载中断**：OneDrive 网页上不能单独下载一本笔记本，只能下载装着笔记本的文件夹；大文件夹的网页下载可能中途失败且不能续传，所以要做好残缺下载包的兜底。插件内直接下载已经做好，可以按分区下载、断点续传。
6. **分区顺序**：按笔记本的目录文件排。OneDrive 上的目录文件有时不跟着分区改名，或缺了某个分区，这些分区排在后面，按名称。
7. **判断“用户改过”**：检查更新看页面文件的修改时间是否还等于页面属性里的修改时间。同步工具或 git 改了文件时间时，会被当作改过（偏保守：只会多留一份，不会丢内容）。
8. **平台**：目前在 macOS 上开发和测试；Windows、Linux 桌面版还没有实测（Linux 上登录信息的保护程度取决于系统的密钥环）。
9. **微软账号的依赖**：直接下载依赖本插件在微软注册的应用；应用不可用时登录会失败（插件会说明），网页下载仍是退路。
10. **下载副本占磁盘**：检查更新时，已导入的笔记本整本存在系统缓存文件夹里；下载前检查剩余空间，设置页可以删除。
11. **中国大陆**：OneDrive 网站在大陆打不开，直接下载可能对这些用户最有用，但在大陆网络下还没有实测。

## 9. 已知限制

README 里列了最主要的几条，这里是完整的清单。大多数情况很少见；碰到了请在 GitHub 上告诉我们。

### 9.1 转换

1. 页面的自由排版（精确位置、字体、字号）不还原，文本框按阅读顺序排列（第 4 节第 1 条）。
2. 文本框里的图片，OneNote 不记它的位置，图上的手写和荧光笔按估算放；没把握时图片保持原样，另附一份折叠的估算副本。表格里的图片同样按估算；嵌套表格（格子里又有表格，整张当排版写）里的图片上的笔迹不按图放，手写照旧单独成图、荧光笔不导出。打字文字上和空白处的荧光笔不导出。
3. 设了密码的分区读不出，请先在 OneNote 里取消密码。
4. Windows 版打印页里有少数画法画不出同样的效果（例如某些裁剪和图片的变换）：这一页不画，只给原文件的链接，报告里写明。
5. PDF 本身的文字层不读：Mac 版的 PDF 打印页只有 OneNote 识别的文字，扫描件的识别常有错。表格单元格里的图片不写文字框。OneNote 在导入之后才补上的识别文字，要重新转换那个分区才会写进来。
6. Windows 版 OneNote 导出时，有的会把每页的修改时间改成导出的时刻，原来的时间在文件里找不到，页面属性 `modified` 写的就是导出时刻。
7. 少数笔记本的目录文件读不出，这些笔记本的分区按名称排。
8. 故意做坏的文件（字体、压缩包、超大图片）可能让转换很慢或占用很多内存。
9. 高亮叠在彩色字（或下划线、上下标）上时，Obsidian 的编辑视图里那几个字只显示颜色、不显示高亮；阅读视图正常。颜色只能用 HTML 写，编辑视图里 Markdown 的高亮到不了 HTML 里面。同样的原因，彩色字里的 `*`、`_`、`` ` ``、`$`、`\` 在编辑视图里带着反斜杠显示。

### 9.2 导入和更新

1. 只列出你自己 OneDrive 里的笔记本，不包括别人共享给你的。工作或学校账号可能要管理员先批准；世纪互联运营的中国版账号不支持。
2. 从 OneDrive 导入时，导入窗口里的树按名称排；导入后的目录页按 OneNote 里的顺序。导入窗口一直开着时，OneDrive 上分区的变化不会反映到树里；关掉窗口再打开时会重新读取，点开始时勾选的分区按 OneDrive 当时的样子下载。
3. 勾选了但下载失败的 OneDrive 分区，下次显示为“上次未选”，不会自动勾上。
4. OneDrive 上的笔记本只改了名字的大小写时，那次导入或更新会失败，下次重新下载整本。
5. 用比仓库里旧的下载来更新同一本笔记本，可能把页面换回旧的内容（换下来的版本在 `_旧版本` 里）。请用最新的下载或导出来更新。
6. 不是从 OneDrive 直接导入的两本同名笔记本，请导入到不同的目标文件夹：放在同一个文件夹里时，第二本（“名字 (2)”）以后检查不了更新。两个文件夹的目录页带着同一个 OneDrive 编号、报告里又没有记录时，按名字认，可能被当成新笔记本导入。
7. 页面在 OneNote 里换了分区：旧分区里那份留着（目录页列在 OneNote 中已移除的页面下），新分区里再写一份。用户把一页复制或挪进别的分区文件夹时，那里会把它报成 OneNote 里已经没有。
8. 判断一页在 Obsidian 里改过没有，看文件的修改时间是否还等于页面属性里的修改时间。同步工具或 git 改了文件时间时，会被当作改过（偏保守：只会多留一份，不会丢内容）。
9. 不要在两台同步同一个仓库的设备上同时更新，也不要让命令行版和插件同时更新同一个文件夹。更新进行中关闭、重新载入或升级插件时，被打断的分区会记作无法读取；笔记本文件夹的名字和笔记本不同时，被打断的更新不能自动处理完。
10. 导入窗口开着时把磁盘上的下载换掉，树不会马上变；关掉窗口再打开，或点开始时，会发现并重新读取。
11. 部分说明只在鼠标悬停时显示，键盘操作时看不到（读屏软件会读出）。
